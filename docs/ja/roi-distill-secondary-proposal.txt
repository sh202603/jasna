作成日: 2026-10-05

【提案の概要】
BasicVSR++が復元した256px ROIを、軽量な5フレーム・2倍の
ROI Distillモデルで補強する独立したSecondaryRestorerを追加する。
検出器、一次復元モデル、追跡、既存の支援者向け機能は置き換えない。
動画全体の解像度やFPSを変えるのではなく、ROI内の画質を補強する。

モデルの契約:
  入力: FP32 [B,15,256,256]、RGB 0〜1、t−2〜t＋2の5枚
  出力: FP32 [B,3,512,512]、中央フレームの2倍画像
  構造: 24チャンネル、12残差ブロック、Conv2d/ReLU/PixelShuffle
  重み形式: roi-distill-pilot-v1のcheckpoint、architectureとmodelを保持

【実装例】
以下は同期二次復元アダプターの例。
modelには、同じTinyROIEnhancerのモデル定義を構築し、checkpointを
strict=Trueで読み込んだPyTorchモデルを渡す。
モデル定義・ローダー・CLIへの登録はこの例には含まない。

----- Python実装例 開始 -----
import torch

class RoiDistillSecondaryRestorer:
    name = "roi-distill"
    num_workers = 1
    prefers_cpu_input = False

    def __init__(self, model, device, view_window=0):
        self.device = torch.device(device)
        self.model = model.eval().to(self.device, dtype=torch.float32)
        self.view_smoothing_window = int(view_window)

    @torch.inference_mode()
    def restore(self, frames_256, *, keep_start, keep_end):
        if frames_256.ndim != 4 or tuple(frames_256.shape[1:]) != (3, 256, 256):
            raise ValueError("expected RGB [T,3,256,256]")
        if not frames_256.is_floating_point():
            raise ValueError("expected float RGB in [0,1], not uint8/BGR")
        t = len(frames_256)
        ks, ke = max(0, int(keep_start)), min(t, int(keep_end))
        if ks >= ke:
            return []
        results = []
        with torch.autocast(device_type=self.device.type, enabled=False):
            for i in range(ks, ke):
                idx = [min(t - 1, max(0, i + d)) for d in (-2, -1, 0, 1, 2)]
                window = frames_256[idx].to(self.device, dtype=torch.float32)
                if not torch.isfinite(window).all():
                    raise ValueError("non-finite ROI input")
                x = window.clamp(0, 1).reshape(1, 15, 256, 256)
                y = self.model(x)
                if tuple(y.shape) != (1, 3, 512, 512) or not torch.isfinite(y).all():
                    raise ValueError("invalid ROI Distill output")
                results.append(y[0].clamp(0, 1).mul(255).round().to(torch.uint8))
        return results
----- Python実装例 終了 -----

【動作上の要点】
・同じROIクリップの5フレームを使い、別ROIや別シーンの履歴を混ぜない。
・クリップの端だけ、利用可能な端のフレームを繰り返す。
・keep範囲外のフレームも入力文脈には使う。入力を先にkeep範囲へ切らない。
・返すのはkeep範囲の画像だけ。5枚入力から中央の1枚を生成する。
・1枚しかないクリップも1枚だけ出力する。アダプター側で検出を捨てない。
・再帰的な前フレーム出力や28枚のウォームアップ出力は必要ない。
・モデルはセッション開始時に一度だけ読む。入力をin-placeで変更しない。
・通常は一次復元と同じGPUで実行し、CPU往復や動画の中間保存を追加しない。
・push_clip等の非同期メソッドを追加せず、同期SecondaryRestorerとして扱う。

【必要な接続変更】
1. 推論用のモデル定義とcheckpointローダーを専用ファイルへ追加する。
   weights_only=Trueで読み、version、architecture、形状、有限値を検査する。
   12ブロックの重みを6ブロックのクラスへstrict=Falseで読む方法は使わない。
2. jasna/session_config.pyにroi-distillとモデルパス・平滑化設定を追加する。
3. jasna/session_factory.pyの_build_secondary_restorerへ生成分岐を追加する。
4. jasna/main.pyに選択肢とモデルパス等の引数・設定転送を追加する。
5. GUIにも対応する場合は、設定画面・保存・video_session_configと
   video_session_keyへモデルと設定を追加する。モデル交換時はセッションを作り直す。
6. 時間窓、keep範囲、512pxのpadding換算、複数ROI、場面転換、合成をテストする。

既存のRestorationPipeline._run_secondaryは、この出力契約を受け取れる。
crop_buffer.scale_offsetsとBlendBufferには出力倍率に応じた合成処理がある。
Core MLへの変換は不要。最初はPyTorch FP32・バッチ1で確認し、
画質を確認してからバッチ化やTensorRT/FP16を検討する。

【枠のなめらかさ】
view_smoothing_windowはRestorationPipelineが読む既存の能力属性。
0で平滑化なし、2以上でtracking/crop_view.pyの平滑化ビューを利用できる。
まず0で移植を確認し、その後5/15などを同条件で比較する。
平滑化時は既存のview_placementsとsample_view_to_bboxを使って貼り戻す。
アダプター内でもう一度座標を戻すと二重変換になるので行わない。

ただしmiohは補強差分を元のROIへ戻す設計なのに対し、modiの既存ビュー経路は
平滑化ビューの画像全体をサンプリングする。完全に同じ合成方法ではない。
VideoToolboxの時間方向ノイズ補正も、この実装例には含まない。
同じモデルだから同じ画質・ちらつきになるとは保証しない。

【検証状況】
実checkpointを使ったCPUの合成入力で以下を確認した。
・先頭/中央/末尾の5フレーム窓から512pxの有限値出力。
・T=1/2/5、部分keep範囲、空keep範囲、T=0での出力枚数。
・この実装例の出力と、同じ窓を使った元モデル出力の完全一致。
・不正寸法、uint8入力、NaN入力の拒否。
・Jasnaのcrop準備→平滑化ビュー→モデル→bboxへの貼り戻し。

Jasnaへの実登録・CUDA実動画・画質・fps・VRAMは未検証。
軽いモデルだが、速度の具体的な数値はまだ提示できない。
モデルの追加だけで、追跡側の大きな結合ROIや対象数の問題が解消するわけではない。
Jasna側の短い検出の除外・検出途切れ補間の設定は別途存在する。
